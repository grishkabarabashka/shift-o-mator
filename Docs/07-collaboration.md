# Совместная работа

Планировщиков мало (один-два на единицу), работают они обычно только со своей единицей.
Поэтому ([ADR-0011](adr/0011-checkout-instead-of-realtime.md)):

- **Check-out на пару (единица планирования, период).** Один берёт EMEA на сентябрь,
  остальные видят в режиме чтения с плашкой «редактирует Мария с 14:20».
- Автоснятие блокировки по таймауту неактивности.
- Принудительное снятие администратором — иначе кто-нибудь уйдёт в отпуск с зажатым
  сентябрём.
- **Real-time совместного редактирования не делаем.** При таком числе редакторов оно
  добавит сложности больше, чем сэкономит.

## Права

- Планировщик правит свою единицу. Технически может и чужую — запрета нет, но по
  умолчанию работает со своей.
- Остальные читают.

В MVP без бэкенда блокировка эмулируется в репозитории: методы `acquireLock` /
`releaseLock` / `getLock` существуют с самого начала и возвращают правдоподобные
результаты, чтобы интерфейс писался под реальный контракт.
