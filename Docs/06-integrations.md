# Интеграции

## Импорт отпусков из Excel

API у корпоративной системы нет, выгрузка делается руками. Это единственный внешний
источник данных, поэтому импорт проектируется как полноценная функция, а не как костыль.

1. **Вставка из буфера** прямо в таблицу (Ctrl+V из открытого Excel) или загрузка файла.
   Вставка быстрее и потому основной путь.
2. **Маппинг колонок** в интерфейсе, сохраняется как именованный шаблон. Формат выгрузки
   поменяется — правится в интерфейсе, не в коде.
3. **Матчинг людей** по employee ID, при отсутствии — по имени с подсказками и ручным
   подтверждением. Соответствия запоминаются.
4. **Предпросмотр diff**: добавлено N, изменено M, исчезло K. «Исчезло» — самое опасное:
   отпуск отменили или строка просто не попала в выгрузку? Пропавшие записи не удаляются
   автоматически, а помечаются и требуют подтверждения.
5. **Импакт-анализ до применения**: «эти 4 отпуска пересекаются с опубликованными
   сменами — 4 назначения потребуют замены», с пересчётом только затронутых дней.
6. **Индикатор свежести** в шапке: «Отпуска актуальны на 12.08 (3 дня назад)». Без него
   через полгода никто не будет знать, можно ли верить данным.
7. Каждый импорт хранится как батч, откат в один клик.

## Обратный поток

Полностью убрать двойной ввод без API нельзя, но можно свести его к чеклисту:

- **Источник истины по планированию** — эта система. **По отпускам** — корпоративная.
- Экран «to be filed»: список comp days и подтверждённых отсутствий, которые ещё не
  занесены в корпоративную систему, с копированием в буфер в нужном формате и отметкой
  «занесено».
- Поле `syncedToHrAt` делает расхождения видимыми, а не всплывающими в конце квартала.
- Если позже найдётся любой способ дёргать ту систему — интерфейс готов, поменяется
  транспорт.

## Календарь

Экспорт ICS. Инженер один раз подписывается — и смены видны в Outlook на телефоне,
включая comp days и отпуска.

- MVP: выгрузка `.ics` за период.
- Прод: стабильный URL подписки с токеном на каждого человека (`Person.calendarToken`
  заложен в модель сразу).

## Экспорт

XLSX (для тех, кто продолжит смотреть в Excel) и CSV. Экспорт полного состояния в JSON —
для отладки и переноса данных из MVP.
