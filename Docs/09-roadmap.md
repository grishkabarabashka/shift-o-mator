# План работ

| # | Этап | Результат |
|---|---|---|
| 1 | Модель и фикстуры | доменные типы и тестовые данные |
| 2 | Движок: даты, покрытие, comp days, валидация | чистые функции с тестами |
| 3 | Репозиторий in-memory, стор с патчами и undo | работающее состояние |
| 4 | Сетка планирования с клавиатурой и paint | ручное планирование |
| 5 | **Полоса покрытия с тремя уровнями подсветки** | **точка, в которой продукт становится полезнее Excel** |
| 6 | Отсутствия: ручной ввод, comp days с предложением даты | замкнутый цикл планирования |
| 7 | Timeline с линией текущего времени и overlap | оперативный вид |
| 8 | Absence overview с лимитами | летний сценарий |
| 9 | Импорт Excel | снятие двойного ввода |
| 10 | Генератор с объяснениями | ускорение планирования |
| 11 | Экспорт XLSX и ICS | выход наружу |
| 12 | Бэкенд .NET, AKS, блокировки, аутентификация | продуктив |

Этапы 1–6 дают инструмент, которым уже можно пользоваться вместо Excel. Автогенерацию
раньше этого делать бессмысленно: нужны 2–3 месяца реальных данных, иначе справедливость
не на чем считать и алгоритм будет предлагать ерунду.

## Текущее состояние

Закрыты этапы 1–6: инструментом уже можно пользоваться вместо Excel для ручного
планирования. Бэкенда нет, данные — фикстуры с персистом в IndexedDB.

Этап 6 в деталях:

- ручной ввод отсутствий — от выделения в сетке (по записи на каждого выделенного
  человека, одним патчем-батчем) и правкой/удалением через двойной клик по отметке;
- comp days — диалог подтверждения и переноса даты (`PROPOSED` → `SCHEDULED`),
  отметка отгуленным, отклонение; подтверждённый отгул после этого блокирует
  назначение в сетке, как отпуск.
